# 真实粒子地球 · Accurate Particle Earth

一个纯前端、零外链的 **Three.js 3D 粒子视觉系统**。星球由数万颗圆形粒子构成，陆地轮廓来自 **Natural Earth 1:10m** 真实地理数据（world-atlas TopoJSON），不是程序噪声。

线上地址：<https://111qqq333www444.github.io/homepage/>

打开方式：必须通过 HTTP/HTTPS（直接双击 `file://` 会被 CORS 拦住本地数据）

```bash
python3 -m http.server 8000   # 然后访问 http://localhost:8000/
```

## 三、核心技术决策（踩过的坑）

### 1. 陆地判定：光栅化查表，而不是 `d3.geoContains`

| 方案 | 单次耗时 | 20 万采样点 |
| --- | --- | --- |
| `d3.geoContains`（land-10m，40.9 万顶点） | ≈ 39 ms | 约 2 小时，浏览器必然卡死 |
| canvas 光栅化 + O(1) 查表 | ≈ 0.0002 ms | 32 ms |

把真实几何按**等距圆柱投影**画进 `2048×1024` canvas（0.176°/px），再按 `(lon, lat) → 像素` 查表。数据源仍是 Natural Earth 真实几何。

> 额外发现：world-atlas 的 land-10m 环缠绕方向与 d3 的球面约定不一致，实测 `geoContains` 会把大西洋、几内亚湾、南太平洋也判成陆地（恒为 `true`）。所以这里不只是"更快"，是"更快且更准"。

### 2. 光栅化必须处理的两个坑

- **反经线 ±180° 拆分**：经度跳变 > 180° 的边会在展开图上拉出横贯画面的直线。做法是在跳变处切分环，并在对侧边缘补插值点。
- **`fill('evenodd')`**：正确处理内湖（里海、五大湖等），否则湖泊会被填成陆地。

### 3. 内部要"一层雾"，不能是实心球、也不能过曝

内部两层大软粒子填满：4.5 万颗 **Normal 混合**雾体（不透明度 0.05）+ 6 万颗 **Additive** 辉光雾（0.045），半径从 0.16R 填到 0.99R。刻意不加实体球芯——那会变成一个不透明的蓝球，把"粒子感"彻底吃掉。

### 4. 外层"防护罩"要像雾，不能像实心球

两层叠加：1.4 万颗**大号软粒子**（1.02R ~ 1.22R，加色混合，不透明度 0.028）+ 一层**菲涅尔球壳**（BackSide + 加色，`pow(0.72 - dot(N, V), 3.8)`，强度 0.14）。前者给雾感，后者给边缘轮廓。

### 5. 发光只来自陆地蓝点

顶点着色器里给夜侧留了一条自发光通道：

```glsl
vec3 nightC = vec3(0.07, 0.09, 0.15) + vec3(0.26, 0.34, 0.55) * uEmissive;
```

`surfMat` 的 `uEmissive = 0.85`（陆地蓝点微微发亮），内部雾只有 0.06~0.10（几乎不发光）。这样"球体暗 + 陆地点发光"是同一套光照里做出的对比，而不是靠后期硬压。

`UnrealBloomPass(0.34, 0.50, 0.74)`：阈值调到 0.74，雾和外壳完全不起辉，只有陆地点与太阳有轻微光晕。

### 6. 悬浮蓝圈：屏幕固定，地球碰到就消失

用 DOM 圆环而不是 3D 物体，保证它**永远不随相机旋转/缩放移动**。判定方式是算出地球在屏幕上的投影像素半径：

```js
const ang = Math.asin(R / d);
const px  = Math.tan(ang) / Math.tan(fov / 2) * (innerHeight / 2);
```

当 `px >= 圆环半径 - 4` 时移除 `.on`（淡出）。滚轮缩放和手势捏合共用这条判定。

### 7. 城市灯光：夜侧才亮

专门一套着色器，用世界法线与太阳方向点积算夜色权重：

```glsl
float night = 1.0 - smoothstep(-0.12, 0.40, dot(n, uLightDir));
vA = pow(night, 1.30) * tw;   // tw = 轻微闪烁
```

加色混合 + `depthWrite: false`。59 座城市 × 46 点共 2714 个点，成本可忽略。城市标签走 DOM，`localPos → matrixWorld → project(camera)` 投影，只在「面向相机且处于夜侧」时浮现，并按优先级做 38 px 防重叠剔除。

### 8. 依赖全部本地化

`vendor/` 下放 three.js、OrbitControls、后处理链、topojson-client、d3-geo、d3-array 与 `land-10m.json`（3.0 MB）。不依赖任何 CDN，断网也能跑；本地数据缺失时依次回退到在线 jsDelivr 源。

唯一按需加载的外链是 MediaPipe（点开「手势」时才拉），加载失败只影响手势，画面照常。

### 9. 网络健壮性

连接超时 10 秒（`AbortController`）· 4 秒无新数据即判定停滞重来 · 每个源失败重试 1 次再切换（本地 10m → 本地 110m → 在线 10m → 在线 110m）· 全部失败给明确错误 + 重试按钮，**绝不无限卡死**。

## 五、交互说明

- **拖动**旋转视角，**滚轮**缩放（与星球中心保持最小距离 3.2）
- 屏幕中心的**蓝色细圈固定不动**；把地球放大到碰到它，圆圈自动淡出
- **手势**（可选）：点左下角「手势」开启摄像头，拇指与食指**捏合**即可缩放地球，此时只有球体变大变小，圈不动；摄像头小窗右下角可拖拽调整大小
- **城市**：转到夜侧能看到真实城市的暖金色灯光与中文名
- **月亮**在右下方缓慢公转，约 8.7 分钟一圈；转到离镜头太近时会自动收缩淡出
- **左下**显示可见粒子数 / 陆地采样数 / 数据源精度 / FPS
- **右下**全屏
- 转到星球背面可以看到远处的太阳
- 界面上没有任何参数控制面板，打开即最终效果
